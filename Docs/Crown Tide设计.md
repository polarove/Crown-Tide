游戏支持多人游玩

## 技能循环与技能资源
有多个角色，每个角色有冠冕技能和潮汐技能两个角色技能；另有当前武器类型对应的特殊攻击技能，固定显示在 UI 第三个技能槽位。旧附身功能已整体取消。角色拥有信心值，通过命中、击杀敌怪等冠冕事件增加信心（越战越勇），通过受击、招架破防等潮汐事件降低信心。
信心是个正负区间[-67,67]，信心降低到阈值(-33)可以释放潮汐技能，信心降低到最大值(-67)触发潮汐技能爆发，只要放了潮汐技能，冠冕技能获得生命偷取 → 攻击回血 → 再循环
冠冕技能同样，信心增长到阈值(33)可以释放冠冕技能，信心涨满了(67)冠冕技能爆发
使用冠冕技能后，信心值归0；使用潮汐技能后，信心值也归0。
以上规则属于初期设计，先按此实现并试玩；合理性与平衡性待实际游玩验证，后续有需要再调整。
由于潮汐技能需要付出更多风险，因此潮汐技能威力更大，效果更强;

因此存在即不能放潮汐也不能放冠冕技能的情况，就平A，平A打怪涨信心，放冠冕

命中敌怪 / 击杀敌怪 / 多人模式救助队友 / 处于 buff 状态 -> 涨信心，未来还会添加更多机制涨信心，要高度抽象 ICrownEvent.Invoke()
被敌怪命中 / 招架破防 / 多人模式被队友命中 / 处于 Debuff 状态 -> 降低信心，未来还会添加更多机制降低信心，要高度抽象 ITideEvent.Invoke()


## 角色系统

### V 武器特殊攻击技能（2026-10-03 最新决定）

任务：记录 V 技能变化及空手补充。开发者：CCvTDD；Agent：Codex（/root）。由Codex记录。

- V 键改为释放当前武器类型的专属特殊攻击技能；封装为独立主动技能，纳入统一释放条件和冷却管理。
- 固定的是 UI 第三个技能槽位置，技能内容由当前武器类型决定，按武器类型播放对应动作与表现。
- 空手默认使用拳头，拳头也是武器类型，拥有自己的 V 技能；武器物品槽为空不代表 V 技能不可用。
- 装备武器表示提供／切换对应技能，不是在装备瞬间自动释放。
- 玩家与 AI、单人与多人共用底层技能释放和表现规则；不代表联机已实现。
- 武器技能要求非零信心，但不消耗信心，释放后不归零；有效命中仍走命中信心事件。成功释放开始独立冷却，换武器保留剩余冷却。默认 V／LB，可在设置改绑；冷却参数可配置。演示按主手、其次副手、最后拳头选技能，双持正式策略仍可调整。

最新开发中：保留第三项 Weapon 的释放、冷却、改绑和 HUD；配置指定技能真实击杀敌人时立即附身。技能与附身均不扣资源，伤害 10、冷却 4 秒仍为演示值。附身按最新 [V 技能规范](V键技能设计.md) 实现，验证见 progress.md。

### 统一实体与装备
游戏世界中可操控的角色统一视为Entity，包括玩家操控角色，小兵，精英怪，boss，哪怕是传送门，都具备两种输入，PlayerInputSource接受玩家键鼠/手柄按键输入，AIInputSource 接受来自分配给角色的决策树的输入

决策树根据敌怪类型不同，提供的决策不同，如小兵只会使用平砍，而boss有专属的潮汐/冠冕技能

Entity都有武器栏，左右两个槽位，不同Entity有不同的武器容量，不同的武器类型占据的容量不同，如匕首只消耗2点容量，那么若角色有4点容量，他就可以双持匕首（2+2=4），但无法装备大剑（6点容量），而可以单持大锤（3点容量，小于4，但3+3>4）

Entity都有饰品栏、护甲栏，以及冠冕、潮汐两个角色技能栏；UI 第三个技能槽固定提供当前武器类型的特殊攻击技能。Entity的能力取决于武器容量、武器、饰品、护甲和角色技能。装备栏与两个角色技能栏允许为空；武器物品槽为空时按拳头提供 V 技能，第三槽仍有对应技能。

护甲分部位，Head / Chest / Legs / Feet，有套装效果，分别在2件套/4件套生效，2件套时只有2件套生效，4件套时则同时生效2件套与4件套的效果，护甲如果没有所属的套装就是散件

武器也是护甲套装的一部分，而武器的套装效果是触发指定套装的2件套/4件套效果时，触发武器自身的2件套/4件套效果

同样的，套装效果也按照buff的思路去做，套装buff生效就是一个持续时间为永久的正面/负面buff，套装脱下后就从Entity的buff列表摘除这个buff

上述装备系统 & 角色系统 & PlayerInput + (AIInput & 决策系统)对所有Entity一视同仁，玩家操控角色，玩家队友、小怪、精英怪、boss、哪怕是坐骑、召唤物等

上述角色系统以传送门举例，同样具备PlayerInputSource和AIInputSource、血量、饰品栏、装备栏、冠冕 & 潮汐技能栏，只不过他的冠冕技能是召唤怪物，潮汐技能是击杀场内所有怪物，且没有装备任何护甲，而饰品栏可以影响他召唤出来的怪的强度；这只是说明机制，不要真的实现传送门，不要过于纠结什么Entity的2个技能分别是什么，发给他们什么技能就用什么，而boss / 精英怪 / 特殊怪就是有指定技能的Entity，高度抽象

## 当前战斗循环（2026-10-03 最新决定）

最新决定覆盖此前“附身取消”：取消的是按 V 直接接管活体的入口，附身过程保留，由指定武器技能造成真实击杀时立即触发；无额外判定窗口。

受击／招架破防／队友命中／Debuff → 降低信心 → 达到潮汐阈值后按键释放 → 信心归零并获得冠冕吸血 → 普攻／武器技能有效命中积累正信心 → 按键释放冠冕并在命中时回血。

V 是武器主动技能的默认按键，第三槽的位置固定，按键可以换绑；技能随当前武器配置变化。它与冠冕、潮汐一起通过统一释放入口；配置了附身效果的技能真实击杀后，由逻辑交接操作者。

## 击杀附身与绿血（2026-10-03）

任务：同步最新口述。开发者：CCvTDD；Agent：Codex（/root）。

每个实体保留红血与独立绿血。正常显示红血，普通死亡红血为零且不可复生；只有被附身时显示绿血。被附身不恢复红血，IsDead 仍为 true。

```text
IsDead = 红血 <= 0
IsPossessed = StateMachine.HasState(被附身)
基础行动资格 = !IsDead || IsPossessed
```

被附身身体沿用正常移动、跳跃、攻击、技能的资格与条件，失控和冷却仍生效。目标持有可延长的限时 Buff，本体持有永久无效果标记；到期、标记移除或双方失效由逻辑清理，原角色死亡归还原视角。释放时记录施放者的 Faith；绿血 = |Faith|×K，时长 = |Faith|×K 毫秒，HUD 显示一位小数秒数。连续技能击杀的实现采用更换载体、始终返回最初本体；不新增附身禁用技能。

被附身时正常伤害扣绿血并沿用伤害修饰／Debuff；绿血耗尽立即返回。死亡／接管保留目标 Buff、Debuff、信心、冷却和状态；技能使用目标资源。K 在共用附身配置上统一调整，演示默认1000（不是正式平衡值）。不制作动画或新增尸体选择入口；敌人木棍／空手拳头共用 V 技能管线。
