游戏名 Crown Tide

> 实现状态（2026-10-03）：附身、相机、基础信心／技能框架、普通近战命中与 AI 普攻已实现；具体角色技能与正式数值仍待配置。临时演示数值已获用户许可，测试占位技能已接通完整机制循环，正式招式与平衡待试玩。见 [信心与技能实现](信心与技能实现.md)、[配置规范](信心与技能配置规范.md)、[近战演示](近战命中与演示验证.md) 与 [循环验证](游戏设定循环验证.md)。

游戏支持多人游玩

## 技能循环与技能资源
有多个角色，每个角色有两个技能，一个是冠冕技能，一个是潮汐技能。角色拥有信心值，通过命中、击杀敌怪等冠冕事件增加信心（越战越勇），通过受击、招架破防等潮汐事件降低信心。
信心是个正负区间[-67,67]，信心降低到阈值(-33)可以释放潮汐技能，信心降低到最大值(-67)触发潮汐技能爆发，只要放了潮汐技能，冠冕技能获得生命偷取 → 攻击回血 → 再循环
冠冕技能同样，信心增长到阈值(33)可以释放冠冕技能，信心涨满了(67)冠冕技能爆发
使用冠冕技能后，信心值归0；使用潮汐技能后，信心值也归0。
以上规则属于初期设计，先按此实现并试玩；合理性与平衡性待实际游玩验证，后续有需要再调整。
由于潮汐技能需要付出更多风险，因此潮汐技能威力更大，效果更强;

因此存在即不能放潮汐也不能放冠冕技能的情况，就平A，平A打怪涨信心，放冠冕

命中敌怪 / 击杀敌怪 / 多人模式救助队友 / 处于 buff 状态 -> 涨信心，未来还会添加更多机制涨信心，要高度抽象 ICrownEvent.Invoke()
被敌怪命中 / 招架破防 / 多人模式被队友命中 / 处于 Debuff 状态 -> 降低信心，未来还会添加更多机制降低信心，要高度抽象 ITideEvent.Invoke()


## 角色系统
游戏世界中可操控的角色统一视为Entity，包括玩家操控角色，小兵，精英怪，boss，哪怕是传送门，都具备两种输入，PlayerInputSource接受玩家键鼠/手柄按键输入，AIInputSource 接受来自分配给角色的决策树的输入

决策树根据敌怪类型不同，提供的决策不同，如小兵只会使用平砍，而boss有专属的潮汐/冠冕技能

Entity都有武器栏，左右两个槽位，不同Entity有不同的武器容量，不同的武器类型占据的容量不同，如匕首只消耗2点容量，那么若角色有4点容量，他就可以双持匕首（2+2=4），但无法装备大剑（6点容量），而可以单持大锤（3点容量，小于4，但3+3>4）

Entity都有饰品栏、护甲栏，两个技能栏（潮汐技能，冠冕技能），Entity的能力高低取决于他武器容量大小、装备了什么武器、饰品栏装备了什么饰品、护甲栏装备了什么护甲、技能栏装备了什么技能，所有栏位都可空，即为什么都没有

护甲分部位，Head / Chest / Legs / Feet，有套装效果，分别在2件套/4件套生效，2件套时只有2件套生效，4件套时则同时生效2件套与4件套的效果，护甲如果没有所属的套装就是散件

武器也是护甲套装的一部分，而武器的套装效果是触发指定套装的2件套/4件套效果时，触发武器自身的2件套/4件套效果

同样的，套装效果也按照buff的思路去做，套装buff生效就是一个持续时间为永久的正面/负面buff，套装脱下后就从Entity的buff列表摘除这个buff

上述装备系统 & 角色系统 & PlayerInput + (AIInput & 决策系统)对所有Entity一视同仁，玩家操控角色，玩家队友、小怪、精英怪、boss、哪怕是坐骑、召唤物等

上述角色系统以传送门举例，同样具备PlayerInputSource和AIInputSource、血量、饰品栏、装备栏、冠冕 & 潮汐技能栏，只不过他的冠冕技能是召唤怪物，潮汐技能是击杀场内所有怪物，且没有装备任何护甲，而饰品栏可以影响他召唤出来的怪的强度；这只是说明机制，不要真的实现传送门，玩家同样可以附身到传送门上，释放冠冕技能召唤敌怪、释放潮汐技能击杀场内所有怪物，不要过于纠结什么Entity的2个技能分别是什么，发给他们什么技能就用什么，而boss / 精英怪 / 特殊怪就是有指定技能的Entity，高度抽象

## 核心玩法
附身是核心玩法（需求钦定）：玩家附身敌怪 → 用敌怪打自己的原角色 → 命中降低原角色信心
（潮汐方向）→ 信心贴边后释放潮汐技能；

附身的输入流转
```
玩家角色（PlayerInputSource →AIInputSource ）→ 敌怪（AIInputSource→PlayerInputSource）→ 倒计时 → 敌怪（PlayerInputSource→AIInputSource）→ 玩家角色（AIInputSource→PlayerInputSource）
```

附身要做成主动技能，就像其他技能一样检查释放条件，但不放在技能栏里，也不是被动技能，属于每个角色固有的技能
附身开始后使用buff计算附身持续时间和结束条件，附身的持续过程由两个buff管理，但计时只放在被附身者身上，原本操控的角色持有一个无效果的永久buff
这样在多人联机环境下，根据目标有没有对应buff，即可判断他是本人、还是正在附身、还是被附身中
## 待确认的配置边界

满值爆发已确定为按键释放强化版本，不自动释放。Buff／Debuff 的信心结算频率与范围、潮汐后吸血比例与时长尚未明确。暂不写成已定案参数，保持原设计描述，后续确认后再实现。传送门仍只作机制例子，不要求实现。
