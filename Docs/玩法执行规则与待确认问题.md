## 2. 已确定的设计边界

### 架构与角色

- 遵循数据驱动：装备、技能、效果与角色差异尽量通过配置表达。
- 所有技能统一处理释放条件；所有持续效果通过 Effect 管理；行为状态通过状态机管理转换与互斥。
- Input 回答“做什么”，Brain 编排执行，Logic 读取并修改 Data、通过 Capability 查询能力，Physics 执行运动，Presentation 呈现结果。
- Data 不调用 Logic；Presentation 对玩法数据只读。Network 横切，聊天记录中的当前阶段仅预留接缝。
- 玩家、敌怪、Boss、坐骑、召唤物等统一为 Entity，差异来自配置、装备、技能和决策内容。传送门仅为说明抽象能力的例子，不要求实际实现。
- 左右武器槽按容量判断装备与双持；护甲、饰品、武器与两类技能槽均允许为空。
- 护甲二件、四件效果累加；武器可在指定护甲套装档位激活时触发自身对应效果。
- 套装效果作为永久 Effect 存在，破套后移除。

### 信心与技能循环

- 信心范围 `[-67, +67]`；冠冕方向阈值 `+33`，潮汐方向阈值 `-33`；满值对应爆发。
- 命中、击杀敌怪、救助队友、相关 Buff 等通过冠冕事件增加信心；受击、破防、队友命中、相关 Debuff 等通过潮汐事件降低信心。
- 两类技能释放后信心归零。中间区间可能两种技能都不可用，通过普攻继续积累。
- 潮汐承担更多风险，预期威力与效果更强；释放潮汐后，冠冕获得生命偷取。吸血具体范围与时长尚未确定。

### 附身

- 附身是每个角色共有的主动技能，不占冠冕／潮汐槽位，统一检查释放条件。
- 默认被控制时不能释放，但要保留解控类技能等例外，不能写成绝对禁止。
- 原角色切到 AI，目标切到玩家输入；结束后归还控制权。
- 目标持有限时“被附身”Buff，原角色持有无数值／控制效果的永久标记 Buff；只有目标计时。
- 释放时确定初始时长，期间允许延长；到期返回原角色并清除双方 Buff。
- 原角色死亡时立即返回视角，经过死亡检查后清除双方 Buff；死亡视角的具体行为待明确。

## 3. 执行问题与建议（全部待确认）

### 01｜附身期间，原角色 AI 是否能消耗技能

**问题：** 玩家操控敌怪攻击原角色，负信心积累在原角色身上。若 AI 自动放潮汐，会提前消耗资源；若玩家要亲自释放，需要返回时机。

**建议：** 第一版原角色 AI 可以移动、普攻、防御，但出窍期间不自动释放冠冕／潮汐；返回后由玩家决定。

**待确认：** 是否接受此限制，以及原角色 AI 的目标、反击与防御策略。

### 02｜潮汐后的回血如何连接信心归零

**问题：** 潮汐释放后归零，暂时不能释放冠冕。如果吸血只作用于冠冕技能，必须先积累到 `+33`，与“攻击回血”之间存在空档。

**建议：** 潮汐给原角色施加限时吸血 Effect，期间普攻与冠冕造成的伤害均可回血；比例、时长通过数据配置。

**待确认：** 普攻是否吸血、是否排除持续伤害、效果时长与刷新／叠加规则。当前设定只明确冠冕获得生命偷取，扩大到普攻是建议。

### 03｜满值爆发是否自动释放

**问题：** “达到最大值触发爆发”可能表示自动释放，也可能表示下一次技能强化。

**建议：** 满值不自动释放；下一次主动释放使用强化版。达到阈值后可以先用普通版，或继续积累爆发。

**待确认：** 是否采用主动强化；按键请求、释放失败、起手中断分别在什么时候消耗信心。建议仅在技能被正式接受释放时结算，避免请求失败也归零。

### 04｜附身双方与控制者如何关联

**问题：** 两个 Buff 能表达状态，却不能仅凭“存在”判断应返回哪名玩家、哪个角色。

**建议：** 在附身运行时数据中保存控制者、原角色、目标以及本次关联标识；效果挂摘仍驱动生命周期，不必因此引入全局单例管理器。

**待确认：** 关联数据的具体归属。多人最终需要权威端检查与控制权归属，Buff 判定本身不等于联机已实现。

### 05｜单侧计时与延长

**问题：** 两侧独立倒计时可能不同步；改共享 Effect 资产会影响其他实体的效果实例。

**建议：** 目标效果实例持有初始／剩余时长；原角色标记永久。延长只修改目标本次实例，结束时联动清理标记。

**待确认：** 延长触发来源、增加量、是否有上限。可先留接口，不先添加未指定的玩法。

### 06｜正常结束的统一流程

**问题：** 各处分别换绑、移除效果，容易只清理一侧或重复归还。

**建议：** 统一结束入口，完成目标回 AI、原角色恢复控制、双方效果及关联清理。重复调用应安全；全过程避免留下两个实体同时接受同一玩家输入的状态。

**待确认：** 是否允许玩家提前退出。较早聊天曾要求不能中途退出，当前主设定未重申，应在正式输入规则中明确。

### 07｜死亡、消失与视角返回

**问题：** 死亡后返回视角不等于把玩家输入重新绑定到死亡角色；目标死亡／卸载也不能等正常倒计时。

**建议：** 目标死亡或消失时，原角色存活则返回；原角色死亡时结束附身并进入死亡视角，不恢复正常操作。两侧都无效时仍清理关联。

**待确认：** 死亡相机、观战或复活流程，以及两侧同帧死亡的处理。

### 08｜附身 Buff 是否可被驱散

**问题：** 普通净化若只移除其中一个 Buff，可能破坏控制权关系。

**建议：** 第一版两个附身 Buff 不参与普通驱散；专用强制结束通过统一结束入口处理。

**待确认：** 是否存在反附身／驱魂技能。若允许驱散，也必须触发双方收尾。

### 09｜Effect 与状态机的职责

**问题：** 若眩晕 Effect 和眩晕状态各维护一份时间，会出现控制已结束而状态仍阻塞等差异。

**建议：** Effect 管存在与时长；状态机管行为、打断与互斥，跟随效果变化进入／退出，不重复计时。

**待确认：** 多种控制同时存在时的优先级、覆盖及解除后的恢复行为。

### 10｜被控制期间的技能例外

**问题：** 绝对禁止技能会连解控技能一起拦住；完全放开又使普通技能绕过控制。

**建议：** 默认禁止，按技能配置允许在哪些控制状态下释放；解控技能通过检查后移除指定控制 Effect。附身默认无例外。

**待确认：** 哪些技能属于例外、解除哪些控制，以及能否仅靠自身技能解除。

### 11｜队友伤害与潮汐资源

**问题：** 无限制友伤可能成为安全刷潮汐的方法，削弱附身承担风险的意义。这是平衡风险，不是逻辑错误。

**建议：** 第一版保留友伤降信心，实际产生有效伤害才触发；完全免伤不降低，之后通过试玩决定是否限制。

**待确认：** 变化量是否按伤害比例、是否需要频率限制。不预先禁止用户已经指定的友伤机制。

### 12｜信心事件的次数与归属

**问题：** 每帧触发、一次伤害重复上报、多段攻击或持续跳伤，都可能瞬间填满信心；“处于 Buff／Debuff”也未明确触发频率。

**建议：** 命中按有效伤害结算一次，击杀另算一次；持续效果按配置间隔触发。事件变化量可配置，信心写回统一入口。

**待确认：** 持续伤害是否算命中、每段是否计数、Buff 进入时是否立即触发。敌我判定要明确：附身攻击原角色应让原角色受击降信心，攻击者是否涨信心不能仅按“当前玩家控制”判断。

## 4. 其他实现边界

- **技能与身体归属（建议）：** 控制哪具身体，就使用该身体的装备与技能；原角色信心留在原角色，返回后使用。控制权切换本身不搬运血量、信心或装备。
- **武器套装（待确认）：** 建议武器不额外计入四件护甲数量，而是在指定护甲套装达标后激活自身效果；应明确双持时两把武器是否分别生效。
- **冠冕“小”、潮汐“大”：** 表示玩法定位和预期收益，不意味着冠冕没有满值爆发。
- **依赖图：** 区分帧内执行顺序和源码依赖。Brain 可以编排各层，不要求 Physics 依赖 Presentation；Data 不得回调 Logic 来执行套装等玩法计算。

## 6. 建议实现顺序与验收场景

建议先确认第 01、02、03 项，再按以下顺序推进：

1. 修通附身控制权往返、双侧关联、单侧计时、死亡与强制结束。
2. 接通攻击命中扣血与信心事件，验证附身目标可以攻击原角色。
3. 落实阈值、强化释放、归零与潮汐后的吸血效果。
4. 加入 AI 行为与技能例外，再通过试玩调整风险收益；网络接缝之后兑现。

若采纳本文建议，验收至少覆盖：

- 附身开始后只有目标接受该玩家输入，原角色由 AI 行动；到期准确返回。
- 原角色标记不自行到期；延长目标效果不会修改其他会话或共享资产。
- 目标死亡、原角色死亡、目标消失、强制结束都清理双方；重复结束安全。
- 两位控制者各自附身不会串号，同一目标不能被重复占用。
- 控制期间普通技能和附身被拒绝，配置了例外的解控技能可用。
- 阈值内不能释放，阈值解锁，满值强化；拒绝释放不归零，成功释放按确定的结算点归零。
