## 实现边界

附身是固有主动技能，不占冠冕／潮汐槽位。V／手柄 LB 通过 Possess 动作写入指令，由 Brain 消费；附身和槽位技能都调用 `Capability.CanUseSkill`。默认死亡、被控制或已有主动动作时不能起手；技能配置可以显式允许被控制期间释放。

信心与技能的新配置目标见 [信心与技能配置规范](信心与技能配置规范.md)。2026-10-03 已另行实现 ±33 阈值、±67 按键强化、释放归零与事件基础框架，见 [信心与技能实现](信心与技能实现.md)；本页历史附身测试结果不作为新机制验收依据。

持续过程由两个 Effect 管理：目标的 `Possessed` 实例计时，原角色的 `SoulOut` 实例永久存在。`EntityBrain` 中每次附身的运行时关联记录双方和原输入源，不设全局场景管理器，不修改共享效果资产。

```text
玩家原角色 → AI；目标 → 玩家
目标效果倒计时／ExtendPossession(seconds) 延长本次实例
到期或结束 → 目标恢复原输入；原角色恢复原输入；清理双方效果与关联
```

- 已在出窍或被附身状态的双方不能嵌套发起；缺失或配错两种效果时拒绝，不部分写入。
- 两个效果是纯标记：不能夹带数值、控制、周期伤害或其他标签载荷。
- 原角色 AI 不因出窍标记停止采集指令；本次不新增其自动选招策略。
- `EndPossession()` 是双方通用、可重复调用的结束入口；玩家 V／LB 不主动结束。
- 任一效果被移除、实体禁用／销毁、双方任一死亡，都结束关联并清理双方。
- 原角色死亡时保留返回视角，停止玩家角色操作；完整死亡 UI、复活、队友观战另属后续系统。
- 周期伤害导致死亡时，效果遍历完成后收尾，避免遍历中删除条目。
- AI 可使用固有附身入口，但不能因此凭空取得本地玩家输入。

## 文件与 API

- `EntityBrain.cs`：`TryBeginPossession`、`ExtendPossession`、`EndPossession`、`HasSoulOut`、`PossessionRemaining`、`HasPlayerView`。
- `ModifierList.cs`：时长实例快照、永久时长覆盖、`ExtendDuration`，共享资产不作运行时写入。
- `PlayerInputSource.cs`／`CommandBuffer.cs`：Possess 动作（V／LB）提交附身请求，切换时清理旧输入与边沿指令。
- `EntityCapabilities.cs`：共用技能释放门禁。
- `CameraRig.cs`：只读视角归属，死亡返回视角不等于恢复操作。
- 演示生成与校验工具：原角色标记永久，校验两种效果角色与时长。
