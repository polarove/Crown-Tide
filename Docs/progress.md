### 3. 释放、结算与交接的执行顺序

```text
V／LB／改绑后的动作 → 第三槽技能请求
  → Capabilities：基础行动、控制状态、动作占用
  → SkillSlot：已装配、Faith非零、冷却、攻击配置
  → Brain：检查附身配置，记录施放时Faith并计算abs(Faith)×K
  → 换算值有效才提交冷却 → 进入技能攻击 → 命中窗口采样
  → ResolveHit：正常伤害修饰 → 扣目标红血 → 统计实际损血
  → 正常命中／红血击杀信心事件
  → 本次Weapon技能造成真实敌方红血击杀且交接条件成立
  → 取消施放者旧命中段 → 初始化目标绿血、施加双方标记
  → 设置独立附身身份 → 本体自身AI／目标自身玩家输入接管
```

只命中未击杀、普攻击杀、重复攻击普通尸体均不触发。信心快照发生在命中前，因此击杀涨信心不会增加本次绿血或时长。成功释放但没有击杀仍会进入冷却，这属于正常技能释放。

附身中，正常受击或周期伤害仍先走 TakeDamage 的伤害修饰，再扣绿血。ResolveHit 在伤害前保存使用红血还是绿血，避免耗尽后身份已清除导致损血统计错误。冠冕吸血按实际损血恢复施放者当前有效生命；被附身时恢复绿血，不复活红血。

### 4. 生命周期、继承与修正点

- **唯一计时**：目标 ModifierList 中的被附身 Buff 保存剩余秒数；本体持有永久标记，不另建第二个倒计时。共享 Carrier 模板的10秒只是模板默认，实际施加时以快照换算秒数覆盖。
- **动作继承**：BindInputSource 新增明确的 `preserveAction` 选项；附身接管和返回使用该选项。新目标的已有动作、失控层和其他状态不因换输入源被主动清空；普通换源保持既有默认行为。
- **终止旧命中段**：只保留新目标状态，不保留施放者当前夺取动作。审查修正了连续附身时旧载体动作可能继续采样的问题，取消当前施放者动作后再更换载体。
- **连续附身**：当前实现允许被附身身体用自身技能真实击杀后更换载体，最终归还最初本体；不额外禁用V。仍按新施放实体自己的信心快照计算下一次绿血／时长。
- **退出**：到期、绿血耗尽、附身标记不再持有或身份失效时结束；原本体死亡、实体停用／销毁也走生命周期收尾。移除双方附身标记和关联，恢复捕获的输入源；目标红血仍为0，其他 Buff和资源保留。
- **周期迭代**：ModifierList 正在遍历时不直接删双侧列表；迭代完成后的 Reconcile 接缝再清理，防止跳过效果或越界。
- **失败不消费**：非法K、非有限／溢出／无法形成正时长的换算值，在提交冷却前拒绝，不能先消费再发现无法初始化附身。
